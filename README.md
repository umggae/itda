# 잇다

자동차뿐만 아니라 **대중교통을 이용할 때**도, 여러 곳을 경유하는 일정의 구간별 이동시간과 방문 순서를 검사하고 더 효율적인 순서를 제안해 주는 서비스입니다.

최종 목표는 전국이지만, 현재는 서울만 범위입니다.

## 목적

지도 앱은 두 곳 사이의 이동시간과 방법은 잘 알려 주지만, 하루에 여러 곳을 들를 때에는 이를 한 번에 보기 어렵습니다. 이동수단이 도보, 자전거, 자동차일 때는 경유지 추가가 가능한 서비스들이 많지만, 네이버·카카오 지도에서는 대중교통일 때 경유지를 지원하지 않습니다(카카오맵 공식 문서에도 대중교통은 경유지를 지원하지 않는다고 적혀 있습니다). 잇다는 이 불편을 해결합니다.

핵심 흐름: **일정 입력 → 검사 결과 확인 → 순서 제안 적용 → 공유 링크 생성**

## 사용자

서울에서 하루 일정을 대중교통으로 짜는 여행객입니다. 하루 안에 여러 곳을 들러야 해서, 매번 지도 앱에서 출발지와 도착지를 여러 번 바꿔 가며 구간별 시간을 확인하는 것이 불편했던 사람을 생각했습니다.

서비스: [https://itda-rho.vercel.app/](https://itda-rho.vercel.app/)

저장소: [https://github.com/umggae/itda](https://github.com/umggae/itda)

## 사용법

1. 이동수단 선택 (대중교통 / 자동차) 및 날짜와 하루 시작·종료 시각 입력.
(기본입력값: 오늘, 오전 9시 ~ 오후 9시로 설정돼있습니다.)
2. 출발지와 도착지를 검색해 주소를 확인한 후 선택.
3. 경유지 추가가 필요한 경우, 들를 장소를 검색해 추가.(최대 6곳)
경유지는 선택이며, 없으면 출발지에서 도착지까지 한 구간만 검사합니다.
방문 순서는 ▲▼ 버튼으로 변경 가능하며, 체류시간(분) 수정 가능. (기본: 음식점 30분, 그 외 60분)
4. 일정 검사하기 클릭해 결과 확인
    1. 가능/불가능 (시간이 초과될 경우 초과 시간과 문제 구간이 표시됨)
    2. 장소별 도착·출발 시각, 구간별 소요시간 및 거리, 대중교통의 노선, 탑승시간, 배차간격, 카카오맵 길찾기 링크 확인 가능.
    3. 더 효율적인 순서 제안 선택 가능
    (이 순서로 적용 or 지금 순서 유지)
    4. 가기 전 확인할 것
5. 공유 링크 만들기: 일정이 담긴 주소를 다른 사람에게 공유 가능
6. 새 일정으로 저장: 브라우저에 일정 저장. 여러 개를 저장할 수 있고, “저장한 일정” 메뉴에서 확인 가능.

## 데이터 출처와 갱신일

**갱신일**: 없음. 실시간 조회.

| 용도 | 출처 | 비고 |
| --- | --- | --- |
| 여행지·음식점 검색, 쉬는 날·이용시간·주차 등 정보 | 한국관광공사 TourAPI(공공데이터포털) | 등록되어 있지 않은 항목은 “정보 없음”으로 표시 |
| 출발지·도착지 검색, 장소 좌표 | 카카오 로컬 API |  |
| 대중교통 이동시간·노선·탑승 시간·배차 간격 | Google Routes API | 지하철 배차 간격은 열차 시각으로 어림한 값이며 “(추정)”으로 표시 |
| 자동차 이동시간·거리 | 카카오모빌리티 길찾기 API |  |
| 지도 | Leaflet + OpenStreetMap |  |
| 길찾기 링크 | 카카오맵 URL |  |

**인증키는 코드·커밋·화면·로그에 넣지 않았고, Vercel 환경 변수에만 둡니다.** (과제 안내는 GitHub Secrets를 예로 들지만, 서버 사용을 허락받아 서버 함수가 키를 쓰는 구조라 Vercel 환경 변수를 썼습니다.) 

**이용 조건**: 각 서비스는 이용 신청·키 발급 후 사용했고, 조회 결과 원문을 저장하거나 다시 배포하지 않습니다(지도는 © OpenStreetMap 기여자 표기). 자세한 점검 내용은 [docs/data-sources.md](docs/data-sources.md)에 있습니다.

**개인정보**: 이름·연락처 등 개인정보는 받지 않고, 일정은 서버에 저장하지 않습니다. 저장한 일정은 내 브라우저(localStorage)에만 남고, 공유 링크에는 장소 이름·좌표와 시각·체류시간만 담깁니다. 브라우저는 우리 서버 함수만 부르고 외부 API를 직접 부르지 않습니다.

**검증하며 발견해서 고친 것**

- 안내 문구가 옛 방식(“거점 목록에서 선택”)으로 남아 있어 “검색해 선택”으로 수정했습니다. *(발견: 검증 캡처를 Claude와 함께 보다가)*
- 경유지가 6곳일 때 7번째를 추가하면 안내가 화면 맨 위에만 떠서 반응이 없어 보였습니다. 검색칸 아래에도 안내가 뜨도록 고쳤습니다. *(발견: 내가 직접 써 보다가)*
- 검색칸의 ×로 글자를 지워도 이전 검색 결과 목록이 남아 있고, 이름이 긴 결과의 “추가” 버튼 글자가 세로로 깨졌습니다. 둘 다 고쳤습니다. *(발견: 내가 직접 써 보다가)*
- 자동차에서 날짜를 1년 뒤로 바꿔도 정상 결과가 나와 혼란스러웠습니다. 자동차는 날짜를 쓰지 않는 것이 원인이어서, 이동수단별 안내 문구를 추가했습니다. *(발견: 내가 직접 써 보다가)*
- 자동차 결과에 대중교통 전용 설명이 보이고 같은 거리가 두 번 나와서 정리했습니다. *(발견: 자동차 캡처를 Claude와 함께 보다가)*

## 알려진 한계

- **지역은 서울만**입니다(전국 확장은 이후 과제).
- **지하철 배차 간격은 추정값**입니다. 구글이 지하철 배차 간격을 주지 않아, 열차 시각을 이용해 어림합니다. 버스는 구글이 주는 값을 그대로 씁니다. 이후 공공데이터(역별 시간표 등)로 정확도를 개선할 수 있습니다.
- 대중교통 이동시간 표는 모든 구간을 **시작 시각 기준**으로 계산합니다. 오후 구간은 실제와 다를 수 있습니다.
- 대중교통은 **오늘 기준 약 6일 전~99일 뒤** 날짜만 조회됩니다. 자동차는 날짜·시각을 쓰지 않으며 실시간 교통 예측이 아닙니다.
- 지도의 선은 장소를 **직선으로 이은 것**이며 실제 이동 경로가 아닙니다. 길찾기 링크는 카카오맵만 연결합니다.
- 저장한 일정은 **이 브라우저에서만** 보입니다(기기 간 동기화 없음, 사이트 데이터를 지우면 사라짐). 다른 기기로는 공유 링크로 옮깁니다. 최대 50개입니다.
- TourAPI는 대표 명소가 검색에서 빠지거나 단어의 일부로는 찾지 못할 수 있고, 등록되지 않은 상세 정보는 “정보 없음”으로 나옵니다. 카카오 검색으로 찾은 장소(역·터미널·숙소 등)에는 영업시간 정보가 없어서 카카오맵·네이버 검색 링크로 대신합니다.
- 인터넷이 끊긴 상황은 직접 시험하지 못했습니다(오류 안내 코드는 있습니다).
- 공개 주소라 누구나 서버 함수를 호출할 수 있고 호출 횟수 자체는 제한하지 않아, 외부 API 사용량과 비용이 늘 수 있습니다(입력 검증과 결과 캐시는 있습니다).
- Google 지도 플랫폼의 이용 약관 중 **다른 지도(OpenStreetMap)와 함께 쓰는 경우**의 조건은 아직 확인하지 못했습니다.

## 사용한 자료와 AI 도움

**사용한 AI : Claude(Anthropic, Claude Code)를 썼습니다.** 

- **AI(Claude)가 한 일**: 코드 대부분(화면, 일정 계산, 서버 함수, 테스트), 공식 문서 조사, 응답 확인용 스크립트, 문서 초안(README 초안 포함). 단계별 작업 내용은 [docs/ai-log.md](docs/ai-log.md)에 기록되어 있습니다.
- **내가 한 일**: 서비스 방향 결정(서울로 범위 확정, 대중교통 경유지 검사에 집중)과 요구(배차 간격 표시, 자동완성 검색, 저장·여러 개 저장, 저장 메뉴 창, 네이버 지도 같은 화면). 각 서비스의 계정·인증키 발급과 Vercel 환경 변수 등록, GitHub·Vercel 배포. 배포된 사이트를 직접 사용하며 문제를 발견하고, 검증 캡처를 찍어 검증 기록을 채웠습니다(폭 360px·키보드 줄은 캡처를 보고 Claude가 문장을 썼고, 다른 줄도 문장을 다듬어 주었습니다).
- **고친 것 구분**: 위 “검증하며 발견해서 고친 것”은 항목마다 누가 발견했는지 적었습니다. 코드 수정은 모두 Claude가 했고, 나는 수정 뒤 배포된 사이트에서 다시 확인했습니다.
- **README**: 초안은 Claude가 썼고, 내가 본인 말로 다시 썼습니다. 작성 후 Claude에게 **최종 점검**(사실 확인, 오탈자, 평가 기준 대응)을 받았고, 지적된 부분은 Claude가 반영해 고쳤습니다.

**사용한 자료**: 한국관광공사 TourAPI, 카카오 로컬·모빌리티·카카오맵 URL 공식 문서, Google Routes API 공식 문서, Leaflet, OpenStreetMap. 코드는 클로드가 HTML·CSS·JavaScript(프레임워크 없음)와 Vercel 서버 함수(Node.js)로 작성했습니다.
