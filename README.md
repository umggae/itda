# 위시루트

자동차뿐만 아니라 **대중교통을 이용할 때**도, 여러 곳을 경유하는 일정의 구간별 이동시간과 방문 순서를 검사하고 더 효율적인 순서를 제안해 주는 서비스입니다.

최종 목표는 전국이지만, 현재는 서울만 범위입니다.

## 목적

지도 앱은 두 곳 사이의 이동시간과 방법은 잘 알려 주지만, 하루에 여러 곳을 들를 때에는 이를 한 번에 보기 어렵습니다. 이동수단이 도보, 자전거, 자동차일 때는 경유지 추가가 가능한 서비스들이 많지만, 네이버·카카오 지도에서는 대중교통일 때 경유지를 지원하지 않습니다(카카오맵 공식 문서에도 대중교통은 경유지를 지원하지 않는다고 적혀 있습니다). 위시루트는 이 불편을 해결합니다.

핵심 흐름: **일정 입력 → 검사 결과 확인 → 순서 제안 적용 → 공유 링크 생성**

## 흐름과 완료 기준

| 흐름 | 완료 기준 (이렇게 되면 이 흐름은 끝난 것) |
| --- | --- |
| ① 일정 검사: 출발지·도착지, 경유지(선택, 최대 6곳), 날짜, 시작·종료 시각을 입력하고 “일정 검사하기” | 정상 입력이면 “가능/불가능”과 장소별 도착·출발 시각, 구간별 소요시간(대중교통은 노선·탑승 시간·배차 간격)이 나온다. 종료 시각을 넘기면 초과 시간과 문제 구간이 강조된다. 입력이 잘못되면(출발지 없음, 시각 오류, 체류시간 오류, 같은 장소 등) 검사 전에 이유와 할 일이 안내된다. |
| ② 순서 제안: 경유지가 2곳 이상일 때 더 짧은 방문 순서를 받아 적용 | 더 짧은 순서와 줄어드는 시간이 제안되고, “이 순서로 적용”을 누르면 순서가 바뀌어 다시 검사된다. 이미 가장 짧으면 제안이 나오지 않는다. |
| ③ 공유와 저장: 공유 링크 만들기, 새 일정으로 저장 | 공유 링크를 새 탭에서 열면 같은 일정이 채워지고 검사까지 끝나 있다. 저장한 일정은 같은 브라우저의 “저장한 일정”에서 불러올 수 있다. |

“가기 전 확인할 것”, 쉬는 날·영업시간 경고는 ①의 결과에 붙는 부가 정보입니다(가능/불가능 판정에는 영향을 주지 않습니다).

## 사용자

서울에서 하루 일정을 대중교통으로 짜는 여행객입니다. 하루 안에 여러 곳을 들러야 해서, 매번 지도 앱에서 출발지와 도착지를 여러 번 바꿔 가며 구간별 시간을 확인하는 것이 불편했던 사람을 생각했습니다.

## 사용법

1. 이동수단 선택 (대중교통 / 자동차) 및 날짜와 하루 시작·종료 시각 입력.
(기본입력값: 오늘, 오전 9시 ~ 오후 9시로 설정돼있습니다.)
2. 출발지와 도착지를 검색해 주소를 확인한 후 선택.
3. 경유지 추가가 필요한 경우, 들를 장소를 검색해 추가.(최대 6곳)
경유지는 선택이며, 없으면 출발지에서 도착지까지 한 구간만 검사합니다.
방문 순서는 ▲▼ 버튼으로 변경 가능하며, 체류시간(분) 수정 가능. (기본: 음식점 30분, 그 외 60분)
4. 일정 검사하기 클릭해 결과 확인
    1. 가능/불가능 (시간이 초과될 경우 초과 시간과 문제 구간이 표시됨)
    2. 장소별 도착·출발 시각, 구간별 소요시간 및 거리, 대중교통의 노선, 탑승시간, 배차간격, 카카오맵 길찾기 링크 확인 가능.
    3. 더 효율적인 순서 제안 선택 가능
    (이 순서로 적용 or 지금 순서 유지)
    4. 가기 전 확인할 것
    5. 쉬는 날·영업시간 경고: 방문 날짜에 쉬는 날일 수 있는 장소, 또는 도착·출발 시각이 영업시간(입장마감·마지막 주문 포함)과 맞지 않는 장소를 결과 위쪽 카드와 일정 옆 표시로 알려 줍니다. 한국관광공사에 등록된 정보라 정확하지 않을 수 있어서, 직접 연락해 확인하라는 안내와 문의처(전화 걸기 링크)를 함께 보여 줍니다. 가능/불가능 판정에는 영향을 주지 않습니다.
5. 공유 링크 만들기: 일정이 담긴 주소를 다른 사람에게 공유 가능
6. 새 일정으로 저장: 브라우저에 일정 저장. 이름을 붙일 수 있고(선택), 여러 개를 저장할 수 있고, “저장한 일정” 메뉴에서 확인 가능. 저장하면 다음 일정을 만들 수 있게 입력 화면이 비워집니다.

## 데이터 출처와 갱신일

**갱신일**: 없음. 실시간 조회.

| 용도 | 출처 | 비고 |
| --- | --- | --- |
| 여행지·음식점 검색, 쉬는 날·이용시간·주차 등 정보 | 한국관광공사 TourAPI(공공데이터포털) | 등록되어 있지 않은 항목은 “정보 없음”으로 표시 |
| 출발지·도착지 검색, 장소 좌표 | 카카오 로컬 API |  |
| 대중교통 이동시간·노선·탑승 시간·배차 간격 | Google Routes API | 지하철 배차 간격은 열차 시각으로 어림한 값이며 “(추정)”으로 표시 |
| 자동차 이동시간·거리 | 카카오모빌리티 길찾기 API |  |
| 지도 | MapLibre GL + OpenFreeMap(OpenStreetMap 데이터) | 인증키 없이 사용 가능, 출처 표기 필수 |
| 길찾기 링크 | 카카오맵 URL |  |

**인증키는 코드·커밋·화면·로그에 넣지 않았고, Vercel 환경 변수에만 둡니다.** (과제 안내는 GitHub Secrets를 예로 들지만, 서버 사용을 허락받아 서버 함수가 키를 쓰는 구조라 Vercel 환경 변수를 썼습니다.) 

**이용 조건**: 각 서비스는 이용 신청·키 발급 후 사용했고, 조회 결과 원문(응답 전체)을 저장하거나 다시 배포하지 않고, 사용자가 고른 장소의 이름·좌표와 시각만 공유 링크·저장한 일정에 담습니다(지도는 © OpenStreetMap 기여자, OpenFreeMap 표기). 자세한 점검 내용은 [docs/data-sources.md](docs/data-sources.md)에 있습니다.

**개인정보**: 이름·연락처 등 개인정보는 받지 않고, 일정은 서버에 저장하지 않습니다. 저장한 일정과 직접 붙인 저장 이름은 내 브라우저(localStorage)에만 남고, 공유 링크에는 장소 이름·좌표와 시각·체류시간만 담깁니다. 브라우저는 우리 서버 함수만 부르고 외부 API를 직접 부르지 않습니다.

## 기술 구성

```
브라우저 (HTML·CSS·JavaScript, 프레임워크 없음)
   │  같은 주소의 /api/* 만 호출합니다 (외부 API를 직접 부르지 않음)
   ▼
Vercel 서버 함수 (Node.js): /api/search · /api/detail · /api/matrix · /api/leg
   │  인증키는 Vercel 환경 변수에만 있음, 입력 검증과 결과 캐시(구글 결과는 제외)
   ▼
한국관광공사 TourAPI · 카카오 로컬 · 카카오모빌리티 길찾기 · Google Routes API
```

| 위치 | 하는 일 |
| --- | --- |
| `index.html`, `css/`, `js/app.js` | 화면. 지도는 MapLibre GL + OpenFreeMap |
| `js/core/` | 계산(시간표·가능 여부·순서 제안·공유 링크·저장·쉬는 날·영업시간). 화면과 네트워크를 건드리지 않는 순수 함수라 테스트하기 쉽습니다 |
| `js/data/` | 데이터를 받는 부분. 실제 서버(`serverProvider`)와 개발용 가짜 데이터(`mockProvider`, 주소 끝에 `?mock=1`)를 같은 모양으로 바꿔 쓸 수 있습니다 |
| `api/`, `server/` | 서버 함수와 외부 API 클라이언트, 입력 검증, 결과 캐시(검색 10분, 장소 상세 6시간, 자동차 이동시간 30분. 구글 Routes 결과인 대중교통 이동시간·탑승 정보는 약관 때문에 캐시하지 않음) |
| `tests/` | 단위 테스트 123개(Node 내장 테스트 러너, `npm test`) |
| `docs/` | 데이터 출처 점검표, 검증 기록·캡처, 설계 문서, AI 사용 기록 |

- **저장:** 서버에 저장하는 데이터는 없습니다. 저장한 일정은 브라우저(localStorage), 공유 링크는 주소에 일정이 담깁니다.
- **배포:** GitHub `main`에 push하면 Vercel이 자동으로 배포합니다. 인증키는 Vercel 환경 변수, 내 컴퓨터에서는 `.env.local`(git에 올라가지 않음)에 둡니다.

- 안내 문구가 옛 방식(“거점 목록에서 선택”)으로 남아 있어 “검색해 선택”으로 수정했습니다. *(발견: 검증 캡처를 Claude와 함께 보다가)*

- 검색칸의 ×로 글자를 지워도 이전 검색 결과 목록이 남아 있고, 이름이 긴 결과의 “추가” 버튼 글자가 세로로 깨졌습니다. 둘 다 고쳤습니다. *(발견: 내가 직접 써 보다가)*
- 자동차에서 날짜를 1년 뒤로 바꿔도 정상 결과가 나와 혼란스러웠습니다. 자동차는 날짜를 쓰지 않는 것이 원인이어서, 이동수단별 안내 문구를 추가했습니다. *(발견: 내가 직접 써 보다가)*
- 자동차 결과에 대중교통 전용 설명이 보이고 같은 거리가 두 번 나와서 정리했습니다. *(발견: 자동차 캡처를 Claude와 함께 보다가)*
- 배경 지도 서버에 접속할 수 없을 때 지도가 빈 흰 화면이고 경로선이 그려지지 않으며 안내도 없었습니다. 빈 배경으로 바꿔 선을 그리고 안내 문구를 띄우도록 고쳤습니다. *(발견: 접속 불가 상황을 Claude와 함께 시험하다가)*
- 경유지가 출발지·도착지와 같은 장소일 때 입력 검사를 통과해 “경로를 찾지 못했습니다(섬 등)”라는 엉뚱한 안내가 나왔습니다. 입력 단계에서 “같은 장소” 안내가 나오도록 고쳤습니다. *(발견: Claude와 경계값을 점검하다가)*
- 일정이 자정을 넘기면 “27:56”처럼 표시됐습니다. “다음 날 03:56”으로 고쳤습니다. *(발견: Claude와 경계값을 점검하다가)*
- 검색칸에 글자 수 제한이 없어 서버 한도(30자)를 넘는 검색어를 보낼 수 있었습니다. 칸에도 30자 제한을 걸었습니다. *(발견: Claude와 경계값을 점검하다가)*
- 쉬는 날·영업시간 경고를 만들면서 “가기 전 확인할 것”에 안내 줄이 없는 장소는 글자 “null”이 보이는 문제가 생겼다가 고쳤습니다. *(발견: 영업시간 경고를 만들며 화면을 확인하다가)*

## 알려진 한계

- **지역은 서울만**입니다(전국 확장은 이후 과제).
- **지하철 배차 간격은 추정값**입니다. 구글이 지하철 배차 간격을 주지 않아, 열차 시각을 이용해 어림합니다. 버스는 구글이 주는 값을 그대로 씁니다. 이후 공공데이터(역별 시간표 등)로 정확도를 개선할 수 있습니다.
- 대중교통 이동시간 표는 모든 구간을 **시작 시각 기준**으로 계산합니다. 오후 구간은 실제와 다를 수 있습니다.
- 대중교통은 **오늘 기준 약 6일 전~99일 뒤** 날짜만 조회됩니다. 자동차는 이동시간 계산에 날짜·시각을 쓰지 않으며(날짜는 쉬는 날 확인에만 씁니다) 실시간 교통 예측이 아닙니다.
- **쉬는 날 경고는 참고용**입니다. 한국관광공사에 등록된 글자 중 “연중무휴”, “매주 X요일”, “1월 1일”만 판단하고, 구역·점포별로 다르거나 읽을 수 없는 표기는 “확인 필요”로 원문을 그대로 보여 줍니다. 공휴일·대체공휴일, 설·추석, “매월 둘째 월요일” 같은 규칙은 계산하지 않습니다(공휴일 문구가 있으면 “달라질 수 있음”만 알립니다). 등록된 정보 자체가 정확하지 않을 수 있습니다.
- **영업시간 경고도 참고용**입니다. “09:00~18:00”, “입장마감·마지막 주문”, “상시 개방”, 달별·요일별·평일/주말로 나뉜 구간만 판단하고(조회한 이용시간 37건 중 29건), 구역별·하절기/동절기·브레이크타임·점포별로 다른 표기와 밤 12시를 넘기는 시간은 “확인 필요”로 원문만 보여 줍니다. 판단에 쓰는 도착·출발 시각은 이동시간 계산 결과라 실제와 다를 수 있고, 출발지는 영업시간을 보지 않습니다.
- 지도의 선은 장소를 **직선으로 이은 것**이며 실제 이동 경로가 아닙니다. 실제 경로가 보이지 않아 아쉽다는 사용자 의견이 있었지만, 약관 문제(아래 Google Routes 항목)와 확인하지 못한 점 때문에 그리지 않았습니다. 길찾기 링크는 카카오맵만 연결합니다.
- 저장한 일정은 **이 브라우저에서만** 보입니다(기기 간 동기화 없음, 사이트 데이터를 지우면 사라짐). 다른 기기로는 공유 링크로 옮깁니다. 최대 50개입니다.
- TourAPI는 대표 명소가 검색에서 빠지거나 단어의 일부로는 찾지 못할 수 있고, 등록되지 않은 상세 정보는 “정보 없음”으로 나옵니다. 카카오 검색으로 찾은 장소(역·터미널·숙소 등)에는 영업시간 정보가 없어서 카카오맵·네이버 검색 링크로 대신합니다.
- 서버 연결이 끊긴 상황은 서버를 꺼서 시험했지만(검증 기록 참고), 기기의 인터넷 자체를 끈 상황과 휴대전화 데이터가 끊기는 상황은 시험하지 못했습니다.
- 공개 주소라 누구나 서버 함수를 호출할 수 있고 호출 횟수 자체는 제한하지 않아, 외부 API 사용량과 비용이 늘 수 있습니다(입력 검증이 있고, 구글 결과를 뺀 결과 캐시가 있습니다. 구글 Routes 결과는 약관 때문에 캐시를 껐기 때문에 대중교통 검사마다 구글을 새로 부르며, 그만큼 속도와 비용이 조금 나빠질 수 있습니다).
- **Google Routes API 약관과 지도 문제(2026-11-24 공식 약관에서 확인).** Google Maps Platform 서비스별 약관(Service Specific Terms) 20.2는 Routes API의 구글 지도 콘텐츠를 “구글이 아닌 지도와 함께” 쓰는 것을 금지합니다(20.1은 구글 지도 없이 쓰는 것을 허용). 이 서비스는 대중교통 이동시간·노선을 Routes API로 받아 OpenFreeMap 지도가 있는 같은 화면에 보여 주므로 이 조항에 해당할 수 있다고 판단합니다. 지도에는 구글 경로를 그리지 않고 장소를 직선으로 이을 뿐이지만, 한 화면에 함께 있다는 점이 문제가 될 수 있습니다. 구글 쪽의 출처 표기 요건(“Google Maps” 로고·글자)을 맞췄는지도 확인하지 못했습니다. 해결하려면 지도를 구글 지도로 바꾸거나 대중교통 데이터를 다른 곳에서 받아야 하며, 이번 학기에는 하지 못했고 이후 과제로 남깁니다. 같은 구글 정책 페이지의 **캐시 제한**은 지키려고, Routes 결과(대중교통 이동시간·탑승 정보)를 서버 메모리와 CDN에서 캐시하지 않도록 바꿨습니다(단위 테스트로 확인).
- **카카오 로컬 API 결과의 표시·저장 범위**도 공식 정책 원문으로 확인하지 못했습니다. 카카오 개발자 포럼 답변에는 타사 지도 위에 표시하는 것은 실시간 호출이면 문제없다는 내용과, 결과를 저장하지 말라는 내용이 함께 있어 엇갈립니다. 이 서비스는 사용자가 고른 장소의 이름·좌표를 공유 링크와 “저장한 일정”에 담습니다.
