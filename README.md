# 위시루트

자동차뿐만 아니라 **대중교통을 이용할 때**도, 여러 곳을 경유하는 일정의 구간별 이동시간과 방문 순서를 검사하고 더 효율적인 순서를 제안해 주는 서비스입니다.

**국내 전국**의 장소를 검색해 사용할 수 있습니다. 다만 **서울 밖의 대중교통 시간은 실제와 크게 다를 수 있어** 결과에 경고를 띄웁니다(아래 “알려진 한계” 참고).

## 목적

지도 앱은 두 곳 사이의 이동시간과 방법은 잘 알려 주지만, 하루에 여러 곳을 들를 때에는 이를 한 번에 보기 어렵습니다. 이동수단이 도보, 자전거, 자동차일 때는 경유지 추가가 가능한 서비스들이 많지만, 네이버·카카오 지도에서는 대중교통일 때 경유지를 지원하지 않습니다(카카오맵 공식 문서에도 대중교통은 경유지를 지원하지 않는다고 적혀 있습니다). 위시루트는 이 불편을 해결합니다.

핵심 흐름: **일정 입력 → 검사 결과 확인 → 순서 제안 적용 → 공유 링크 생성**

## 흐름과 완료 기준

| 흐름 | 완료 기준 (이렇게 되면 이 흐름은 끝난 것) |
| --- | --- |
| ① 일정 검사: 출발지·도착지, 경유지(선택, 최대 6곳), 날짜, 시작 시각(원하면 도착 마감 시각도)을 입력하고 “일정 검사하기” | 정상 입력이면 도착 예정 시각(도착 마감 시각을 설정했으면 “가능/불가능”)과 총 이동시간, 장소별 도착·출발 시각, 구간별 소요시간(대중교통은 노선·탑승 시간·배차 간격)이 나온다. 도착 마감 시각을 넘기면 초과 시간과 문제 구간이 강조된다. 입력이 잘못되면(출발지 없음, 시각 오류, 체류시간 오류, 같은 장소 등) 검사 전에 이유와 할 일이 안내된다. |
| ② 순서 제안: 경유지가 2곳 이상일 때 더 짧은 방문 순서를 받아 적용 | 더 짧은 순서와 줄어드는 시간이 제안되고, “이 순서로 적용”을 누르면 순서가 바뀌어 다시 검사된다. 이미 가장 짧으면 제안이 나오지 않는다. |
| ③ 공유와 저장: 공유 링크 만들기, 새 일정으로 저장 | 공유 링크를 새 탭에서 열면 같은 일정이 채워지고 검사까지 끝나 있다. 저장한 일정은 같은 브라우저의 “저장한 일정”에서 불러올 수 있다. |

“가기 전 확인할 것”, 쉬는 날·영업시간 경고는 ①의 결과에 붙는 부가 정보입니다(가능/불가능 판정에는 영향을 주지 않습니다). 서울 밖이 포함된 대중교통 일정은 ①의 결과에 “시간이 실제와 크게 다를 수 있다”는 경고가 함께 나와야 합니다.

## 사용자

국내에서 하루 일정을 대중교통으로 짜는 여행객입니다. 하루 안에 여러 곳을 들러야 해서, 매번 지도 앱에서 출발지와 도착지를 여러 번 바꿔 가며 구간별 시간을 확인하는 것이 불편했던 사람을 생각했습니다.

## 사용법

1. 이동수단 선택 (대중교통 / 자동차) 및 날짜와 하루 시작 시각 입력.
(기본입력값: 오늘, 오전 9시로 설정돼있습니다.)
도착해야 하는 시각이 있으면 “도착 마감 시각 설정”을 켜서 입력합니다(선택, 켜면 기본값 오후 9시).
2. 출발지와 도착지를 검색해 주소를 확인한 후 선택.
3. 경유지 추가가 필요한 경우, 들를 장소를 검색해 추가.(최대 6곳)
경유지는 선택이며, 없으면 출발지에서 도착지까지 한 구간만 검사합니다.
방문 순서는 ▲▼ 버튼으로 변경 가능하며, 체류시간(분) 수정 가능. (기본: 음식점 30분, 그 외 60분)
4. 일정 검사하기 클릭해 결과 확인
    1. 도착 예정 시각과 총 이동시간. 도착 마감 시각을 설정했으면 가능/불가능 (시간이 초과될 경우 초과 시간과 문제 구간이 표시됨)
    2. 장소별 도착·출발 시각, 구간별 소요시간 및 거리, 대중교통의 노선, 탑승시간, 배차간격, 카카오맵 길찾기 링크 확인 가능(안드로이드에서는 네이버 지도 앱 링크도 표시).
    3. 더 효율적인 순서 제안 선택 가능
    (이 순서로 적용 or 지금 순서 유지)
    4. 가기 전 확인할 것
    5. 서울 밖이 포함된 대중교통 일정: 이동시간과 그 시간으로 계산한 가능 여부·순서 제안이 틀릴 수 있다는 경고 표시
    6. 쉬는 날·영업시간 경고: 방문 날짜에 쉬는 날일 수 있는 장소, 또는 도착·출발 시각이 영업시간(입장마감·마지막 주문 포함)과 맞지 않는 장소를 결과 위쪽 카드와 일정 옆 표시로 알려 줍니다. 한국관광공사에 등록된 정보라 정확하지 않을 수 있어서, 직접 연락해 확인하라는 안내와 문의처(전화 걸기 링크)를 함께 보여 줍니다. 가능/불가능 판정에는 영향을 주지 않습니다.
5. 공유 링크 만들기: 일정이 담긴 주소를 다른 사람에게 공유 가능
6. 새 일정으로 저장: 브라우저에 일정 저장. 이름을 붙일 수 있고(선택), 여러 개를 저장할 수 있고, “저장한 일정” 메뉴에서 확인 가능. 저장하면 다음 일정을 만들 수 있게 입력 화면이 비워집니다.

## 데이터 출처와 갱신일

**갱신일**: 없음. 실시간 조회.

| 용도 | 출처 | 비고 |
| --- | --- | --- |
| 여행지·음식점 검색, 쉬는 날·이용시간·주차 등 정보 | 한국관광공사 TourAPI(공공데이터포털) | 등록되어 있지 않은 항목은 “정보 없음”으로 표시 |
| 출발지·도착지 검색, 장소 좌표 | 카카오 로컬 API |  |
| 대중교통 이동시간·노선·탑승 시간·배차 간격 | Google Routes API | 지하철 배차 간격은 열차 시각으로 어림한 값이며 “(추정)”으로 표시. KTX 같은 열차는 어림하지 않음 |
| 자동차 이동시간·거리 | 카카오모빌리티 길찾기 API |  |
| 지도 | MapLibre GL + OpenFreeMap(OpenStreetMap 데이터) | 인증키 없이 사용 가능, 출처 표기 필수 |
| 길찾기 링크 | 카카오맵 URL, 네이버 지도 앱 URL Scheme | 네이버 지도 링크는 안드로이드에서만 표시 |

**인증키는 코드·커밋·화면·로그에 넣지 않았고, Vercel 환경 변수에만 둡니다.** (과제 안내는 GitHub Secrets를 예로 들지만, 서버 사용을 허락받아 서버 함수가 키를 쓰는 구조라 Vercel 환경 변수를 썼습니다.)

**이용 조건**: 각 서비스는 이용 신청·키 발급 후 사용했고, 조회 결과 원문(응답 전체)을 저장하거나 다시 배포하지 않고, 사용자가 고른 장소의 이름·좌표와 시각만 공유 링크·저장한 일정에 담습니다(지도는 © OpenStreetMap 기여자, OpenFreeMap 표기). 자세한 점검 내용은 [docs/data-sources.md](docs/data-sources.md)에 있습니다.

**개인정보**: 이름·연락처 등 개인정보는 받지 않고, 일정은 서버에 저장하지 않습니다. 저장한 일정과 직접 붙인 저장 이름은 내 브라우저(localStorage)에만 남고, 공유 링크에는 장소 이름·좌표와 시각·체류시간만 담깁니다. 브라우저는 우리 서버 함수만 부르고 외부 API를 직접 부르지 않습니다.

## 기술 구성

```
브라우저 (HTML·CSS·JavaScript, 프레임워크 없음)
   │  같은 주소의 /api/* 만 호출합니다 (외부 API를 직접 부르지 않음)
   ▼
Vercel 서버 함수 (Node.js): /api/search · /api/detail · /api/matrix · /api/leg
   │  인증키는 Vercel 환경 변수에만 있음, 입력 검증과 결과 캐시(구글 결과는 제외)
   ▼
한국관광공사 TourAPI · 카카오 로컬 · 카카오모빌리티 길찾기 · Google Routes API
```

| 위치 | 하는 일 |
| --- | --- |
| `index.html`, `css/`, `js/app.js` | 화면. 지도는 MapLibre GL + OpenFreeMap |
| `js/core/` | 계산(시간표·가능 여부·순서 제안·공유 링크·저장·쉬는 날·영업시간). 화면과 네트워크를 건드리지 않는 순수 함수라 테스트하기 쉽습니다 |
| `js/data/` | 데이터를 받는 부분. 실제 서버(`serverProvider`)와 개발용 가짜 데이터(`mockProvider`, 주소 끝에 `?mock=1`)를 같은 모양으로 바꿔 쓸 수 있습니다 |
| `api/`, `server/` | 서버 함수와 외부 API 클라이언트, 입력 검증, 결과 캐시(검색 10분, 장소 상세 6시간, 자동차 이동시간 30분. 구글 Routes 결과인 대중교통 이동시간·탑승 정보는 약관 때문에 캐시하지 않음) |
| `tests/` | 단위 테스트 145개(Node 내장 테스트 러너, `npm test`) |
| `docs/` | 데이터 출처 점검표, 검증 기록·캡처, 설계 문서, AI 사용 기록 |
- **저장:** 서버에 저장하는 데이터는 없습니다. 저장한 일정은 브라우저(localStorage), 공유 링크는 주소에 일정이 담깁니다.
- **배포:** GitHub `main`에 push하면 Vercel이 자동으로 배포합니다. 인증키는 Vercel 환경 변수, 내 컴퓨터에서는 `.env.local`(git에 올라가지 않음)에 둡니다.

## 알려진 한계

- **서울 밖 시간 정확도:** 네이버 지도와 비교한 서울 밖 3개 구간 중 2곳(경주, 제주)에서 차이가 컸습니다(검증 기록 참고). 이동시간이 틀리면 가능/불가능 판정과 순서 제안도 틀릴 수 있어 결과에 경고를 띄우지만, 경고가 시간을 정확하게 해 주지는 않습니다. 경고 기준은 행정구역이 아니라 서울을 감싸는 직사각형이라 경기 일부에는 경고가 뜨지 않습니다. 서울 안의 시간도 체계적으로 비교하지는 않았습니다.
- **지하철 배차 간격:** 구글이 지하철 배차 간격을 주지 않아, 열차 시각을 이용해 어림한 **추정값**입니다.
- **대중교통 이동시간 표:** 모든 구간을 **시작 시각 기준**으로 계산합니다. 오후 구간은 실제와 다를 수 있습니다.
- **영업시간과 쉬는 날 경고: 참고용**입니다. 등록된 정보 자체가 정확하지 않을 수 있으므로 방문 전에 확인해야 합니다.
- **지도의 선:** 장소를 직선으로 이은 것이며 실제 이동 경로가 아닙니다.
- **Google Routes 약관:** Google Maps Platform 서비스별 약관(Service Specific Terms) 20.2는 Routes API 결과를 구글이 아닌 지도와 함께 쓰는 것을 금지합니다(2026-11-24 확인). 지도에 구글 경로는 그리지 않지만, 이동시간과 노선 정보를 다른 지도와 같은 화면에 보여 주므로 이 조항에 해당할 수 있습니다. 아직 해결하지 못했고, 지도 교체나 다른 교통 데이터 사용은 이후 과제입니다. 구글의 출처 표기 요건을 맞췄는지도 확인하지 못했습니다.
- **그 밖에:** 카카오 검색 결과의 표시·저장 범위는 공식 정책 원문으로 확인하지 못했습니다. 서버 호출 횟수 제한이 없고, 저장한 일정은 이 브라우저에서만 보입니다.

## 사용한 자료와 AI 도움

**사용한 자료**: 한국관광공사 TourAPI, 카카오 로컬·모빌리티·카카오맵 URL 공식 문서, Google Routes API 공식 문서, MapLibre GL, OpenFreeMap, OpenStreetMap. 코드는 클로드가 HTML·CSS·JavaScript(프레임워크 없음)와 Vercel 서버 함수(Node.js)로 작성했습니다.

**사용한 AI : Claude(Anthropic, Claude Code)를 썼습니다.**

- **AI(Claude)가 한 일**: 코드 대부분(화면, 일정 계산, 서버 함수, 테스트), 공식 문서 조사, 응답 확인용 스크립트, 문서 초안(README 초안 포함). 단계별 작업 내용은 [docs/ai-log.md](docs/ai-log.md)에 기록되어 있습니다.
- **내가 한 일**: 서비스 방향 결정(처음에는 서울로 범위를 정해 만들고, 원래 목표였던 전국으로 확장. 대중교통 경유지 검사에 집중)과 요구(배차 간격 표시, 자동완성 검색, 저장·여러 개 저장, 저장 메뉴 창, 네이버 지도 같은 화면). 각 서비스의 계정·인증키 발급과 Vercel 환경 변수 등록, GitHub·Vercel 배포. 배포된 사이트를 직접 사용하며 문제를 발견하고, 검증 캡처를 찍어 검증 기록을 채웠습니다. 코드 수정은 모두 Claude가 했습니다. 검증 중 일부(전국 확장, 도착 마감 시각 등)는 Claude가 확인했고, 일부 기록 문장은 Claude가 작성하거나 다듬었습니다.
- **README**: 초안은 Claude가 썼고, 전부 읽어본 후 수정이 필요한 부분을 고쳤습니다. 작성 후 Claude에게 **최종 점검**(사실 확인, 오탈자, 평가 기준 대응)을 받았습니다.

## 회고

처음에는 친구들과의 여행 일정을 짜는 데 불편함을 느끼고, 가고 싶은 곳을 입력하면 AI가 추천하는 동선을 짜주는 아주 간단한 서비스였습니다. 그런데 서비스를 만들며 대중교통을 통해 여행을 다니는 사람들은 이동경로나 시간을 알아보기가 매우 힘들다는 사실을 깨닫고, 이거다 싶어서 방향을 틀게 되었습니다. 우리나라는 대중교통이 오는 시간을 아주 정확하게 알 수 있고, 지도는 구글과 카카오라는 매우 좋은 오픈 API들이 있었기 때문에 작업은 순조로울 것이라 예상했습니다. 그런데 우리나라의 대중교통 배차를 정확히 계산할 수 있다는 제 생각은 제가 서울토박이었기 때문에 한 착각이었습니다. 현재 완성된 서비스는 시간 정확도 면에서 매우 부족하게 느껴집니다. 실사용을 하기에는 네이버 지도라는 강적을 이기기에 부족한 면이 많으며 딱 개인 프로젝트의 수준이라 생각합니다. 하지만 전공생임에도 프로그래밍에 대한 지식이 거의 없는 수준의 제가 AI한테 명령한 것으로 이런 서비스를 만들었다는 것이 저는 아직도 믿기지 않습니다. 제가 했다기엔 정말 한게 없지 않나 하는 생각이 들고, 앞으로도 비약적인 속도로 발전해나갈 AI가 이제는 인간이 이해 불가능한 수준까지 와버렸기에 미래가 두렵다고 느낍니다. 하지만 이렇게 하나하나 작고 큰 프로젝트들을 완성해 나가며 이 강의를 듣기 이전보다 훨씬 클로드와 친해진 것 같습니다.
