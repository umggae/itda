# 잇다

서울에서 하루 일정을 직접 짜는 사람이, 여러 곳을 들르는 일정을 **대중교통으로도** 검사해 볼 수 있는 웹 서비스입니다.

## 목적

지도 앱은 두 곳 사이의 이동시간과 방법은 잘 알려 주지만, 하루에 여러 곳을 들를 때 **구간마다 몇 분이 걸리는지, 순서가 괜찮은지, 하루 안에 끝나는지**를 한 번에 보기 어렵습니다. 특히 대중교통은 경유지를 넣어 구간별로 비교하기가 불편합니다. 잇다는 이 불편을 줄입니다.

- 사용자가 정한 방문 순서를 그대로 **검사**합니다. 구간별 이동시간·노선, 장소별 도착·출발 시각, 종료 시각 안에 끝나는지(가능/불가능과 초과 시간)를 보여 줍니다.
- 더 짧게 이동하는 순서가 있으면 **제안만** 하고, 적용할지는 사용자가 고릅니다. 일정을 대신 짜 주지는 않습니다.
- 대중교통은 "정확히 몇 시 차를 타는지"보다 **탑승 시간과 배차 간격**을 보여 줍니다. 경유 일정은 실제 시각이 조금씩 달라지기 때문입니다.

핵심 흐름 하나: **일정 입력 → 검사 결과 확인 → (순서 제안 적용) → 공유 링크로 보내기**

## 사용자

**서울에서 당일 자유여행(또는 하루 나들이) 일정을 직접 짜고, 대중교통으로 여러 곳을 돌아다닐 계획인 사람**입니다. 지도 앱을 오가며 "이 순서로 가면 시간이 맞나?"를 확인하던 사람을 생각했습니다.

## 공개 주소

- 서비스: https://itda-rho.vercel.app/
- 저장소: https://github.com/umggae/itda

지도 데이터를 실시간으로 조회하는 서버 함수가 필요해서, 교수님께 서버 사용을 허락받고 GitHub Pages 대신 Vercel에 배포했습니다.

## 사용법

1. **이동수단**을 고릅니다(대중교통 / 자동차). **날짜**와 하루 **시작·종료 시각**을 정합니다.
2. **출발지 검색**에 장소 이름(예: 서울역)을 입력합니다. 입력하면 추천이 뜨고, 고르거나 `검색`을 눌러 선택합니다. **도착지 검색**도 같은 방식입니다.
3. **경유지 추가**에서 들를 장소(예: 경복궁)를 검색해 추가합니다(최대 6곳). 방문 순서는 ▲▼ 버튼으로 바꾸고, 장소마다 **체류시간(분)** 을 고칠 수 있습니다(기본: 음식점 30분, 그 외 60분).
4. **일정 검사하기**를 누릅니다.
5. 결과에서 다음을 확인합니다.
   - 가능/불가능 판정(불가능이면 초과 시간과 문제 구간 표시)
   - **일정 한눈에 보기**: 장소별 도착·출발 시각, 구간별 소요시간·거리, 대중교통의 노선·탑승 시간·정류장 수·배차 간격, 구간마다 카카오맵 길찾기 링크
   - 더 효율적인 순서 제안(`이 순서로 적용` / `지금 순서 유지`)
   - **가기 전 확인할 것**: 쉬는 날, 이용·영업시간, 주차, 예약, 문의처
6. **공유 링크 만들기**로 일정을 주소에 담아 보낼 수 있습니다. 받은 사람은 링크를 열면 같은 일정이 채워지고 바로 검사됩니다.
7. **새 일정으로 저장**을 누르면 이 브라우저에 일정이 저장됩니다. 같은 날짜에도 여러 개를 저장할 수 있고, 위쪽 **저장한 일정** 메뉴에서 불러오기·삭제를 합니다. 불러온 일정을 고쳤다면 **불러온 일정 덮어쓰기**로 바꿀 수 있습니다.

직접 실행해 보려면(개발용): `.env.example`을 참고해 `.env.local`에 키를 넣고 `node --env-file=.env.local scripts/dev-server.mjs`를 실행한 뒤 http://localhost:8765 를 엽니다. 키 없이 화면만 보려면 주소 끝에 `?mock=1`(가짜 데이터)을 붙입니다. 테스트는 `npm test`입니다.

## 데이터 출처와 갱신일

**갱신일: 실시간 조회입니다.** 미리 저장해 둔 데이터 파일이 없고, 검사할 때마다 아래 서비스를 서버가 조회합니다(화면에 보이는 정보는 조회한 시점 기준). 같은 요청의 호출을 줄이려고 서버 메모리에 잠깐만 보관합니다(검색 10분, 장소 상세 6시간, 이동시간 30분).

| 용도 | 출처 | 비고 |
| --- | --- | --- |
| 여행지·음식점 검색, 쉬는 날·이용시간·주차·예약·문의처, 전화·홈페이지 | 한국관광공사 TourAPI(공공데이터포털, 국문 관광정보 KorService2) | 관광공사에 등록된 항목만 있고 비어 있는 항목은 "정보 없음"으로 표시합니다 |

**이용 조건과 개인정보·보안**

- 각 서비스는 이용 신청·키 발급 후 사용했고, 조회 결과 원문을 저장하거나 다시 배포하지 않습니다. 자세한 점검 내용은 [docs/data-sources.md](docs/data-sources.md)에 있습니다.
- **인증키는 코드·커밋·화면·로그에 넣지 않았고, Vercel 환경 변수에만 둡니다.** (과제 안내는 GitHub Secrets를 예로 들지만, 서버 사용을 허락받아 서버 함수가 키를 쓰는 구조라 Vercel 환경 변수를 썼습니다.) 브라우저는 우리 서버 함수(`/api/*`)만 부르고 외부 API를 직접 부르지 않습니다.
- 받는 정보는 일정에 필요한 것뿐입니다(장소, 날짜·시각, 체류시간). 이름·연락처 등 개인정보는 받지 않고, 일정은 서버에 저장하지 않습니다. 저장한 일정은 사용자의 브라우저(localStorage)에만 남고, 공유 링크에는 장소 이름·좌표와 시각·체류시간만 담깁니다.
- 서버 함수는 잘못된 입력(서울 밖 좌표, 장소 수 초과, 형식 오류)을 거부하고, 오류 메시지에 키나 외부 주소를 담지 않습니다.

**검증하며 발견해서 고친 것**

- 안내 문구가 옛 방식("거점 목록에서 선택")으로 남아 있어 "검색해 선택"으로 수정했습니다. *(발견: 검증 캡처를 Claude와 함께 보다가)*
- 경유지가 6곳일 때 7번째를 추가하면 안내가 화면 맨 위에만 떠서 반응이 없어 보였습니다. 검색칸 아래에도 안내가 뜨도록 고쳤습니다. *(발견: 내가 직접 써 보다가)*
- 검색칸의 ×로 글자를 지워도 이전 검색 결과 목록이 남아 있고, 이름이 긴 결과의 "추가" 버튼 글자가 세로로 깨졌습니다. 둘 다 고쳤습니다. *(발견: 내가 직접 써 보다가)*
- 자동차에서 날짜를 1년 뒤로 바꿔도 정상 결과가 나와 혼란스러웠습니다. 자동차는 날짜를 쓰지 않는 것이 원인이어서, 이동수단별 안내 문구를 추가했습니다. *(발견: 내가 직접 써 보다가)*
- 자동차 결과에 대중교통 전용 설명이 보이고 같은 거리가 두 번 나와서 정리했습니다. *(발견: 자동차 캡처를 Claude와 함께 보다가)*
- TourAPI 검색에서 지역 필터를 걸면 경복궁 같은 대표 명소가 빠지는 문제를 실제 호출로 찾아, 지역 필터 없이 서울 좌표로 거르도록 바꿨습니다. *(발견: 내가 실행한 확인 스크립트의 결과를 Claude와 함께 보다가)*

## 알려진 한계

- **지역은 서울만**입니다. 서울 범위 밖의 장소는 받지 않습니다(전국 확장은 이후 과제).
- **지하철 배차 간격은 추정값**입니다. 구글이 지하철에는 배차 간격을 주지 않아, 열차 시각을 이용해 어림합니다. 버스는 구글이 주는 값을 그대로 씁니다. 공공데이터(역별 시간표 등)로 정확도를 높일 수 있습니다.
- 대중교통 이동시간 표는 모든 구간을 **시작 시각 기준**으로 계산합니다. 오후 구간은 실제와 다를 수 있습니다. 노선·배차 정보만 구간별 예상 출발 시각으로 다시 조회합니다.
- 대중교통은 **오늘 기준 약 6일 전~99일 뒤** 날짜만 조회됩니다. 자동차는 날짜·시각을 쓰지 않으며 실시간 교통 예측이 아닙니다.
- TourAPI는 대표 명소가 검색에서 빠지거나 "경복"처럼 단어의 일부로는 찾지 못할 수 있고, 등록되지 않은 상세 정보는 비어 있습니다. 카카오 검색으로 찾은 장소(역·터미널·숙소 등)에는 영업시간 정보가 없어서 카카오맵·네이버 검색 링크로 대신합니다.
- 지도의 선은 장소를 **직선으로 이은 것**이며 실제 이동 경로가 아닙니다. 길찾기 링크는 카카오맵만 연결합니다.
- 저장한 일정은 **이 브라우저에서만** 보입니다(기기 간 동기화 없음, 사이트 데이터를 지우면 사라짐). 다른 기기로는 공유 링크로 옮깁니다. 최대 50개입니다.
- 인터넷이 끊긴 상황은 직접 시험하지 못했습니다(오류 안내 코드는 있습니다).
- 공개 주소라 누구나 서버 함수를 호출할 수 있고, 호출 횟수 자체를 제한하지는 않습니다(입력 검증·캐시·장소 수 제한은 있음). 외부 API 한도를 넘으면 안내 후 잠시 뒤 다시 시도하게 합니다.
- Google 지도 플랫폼의 이용 약관 중 **다른 지도(OpenStreetMap)와 함께 쓰는 경우**의 조건은 아직 확인하지 못했습니다.

## 사용한 자료와 AI 도움

**AI 도움: Claude(Anthropic, Claude Code)를 썼습니다.** 정확히는 이렇게 나눠집니다.

- **AI(Claude)가 한 일**: 이 저장소의 코드 대부분(화면, 일정 계산, 서버 함수, 테스트), 공식 문서 조사와 응답 확인용 스크립트, 문서 초안(이 README 초안 포함). 단계별 작업 내용은 [docs/ai-log.md](docs/ai-log.md)에 기록되어 있습니다.
- **내가 한 일**: 서비스 방향 결정(서울로 범위 확정, 대중교통 경유지 검사에 집중, 일정을 대신 짜 주지 않기)과 요구(배차 간격 표시, 자동완성 검색, 저장·여러 개 저장, 저장 메뉴 창, 네이버 지도 같은 화면). 교수님께 서버 사용 허락, 각 서비스의 계정·인증키 발급과 Vercel 환경 변수 등록, GitHub·Vercel 배포. 배포된 사이트를 직접 사용하며 문제를 발견하고(위 "발견해서 고친 것"), 검증 캡처를 찍어 검증 기록을 채우는 일.
- **고친 것 구분**: 위 "발견해서 고친 것"은 항목마다 누가 발견했는지 적었습니다(내가 직접 써 보다가 찾은 것도 있고, 캡처·실행 결과를 Claude와 같이 보다가 찾은 것도 있습니다). **코드 수정은 모두 Claude가** 했고, 나는 수정 뒤 배포된 사이트에서 다시 확인했습니다.
- **AI가 틀리거나 불확실했던 것**: 처음 만든 TourAPI 검색(지역 필터)이 대표 명소를 빠뜨렸고, 실제 호출 결과를 보고서야 원인을 알았습니다. "버스는 구글이 배차 간격을 준다"는 설명도 처음에는 한 노선만 보고 한 말이어서, 서울 실제 호출로 다시 확인했습니다.

**사용한 자료**: 한국관광공사 TourAPI, 카카오 로컬·모빌리티·카카오맵 URL 공식 문서, Google Routes API 공식 문서, Leaflet, OpenStreetMap. 코드는 HTML·CSS·JavaScript(프레임워크 없음)와 Vercel 서버 함수(Node.js)로 작성했습니다.
