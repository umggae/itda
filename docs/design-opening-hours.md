# 영업시간 경고 설계 (2026-11-24)

쉬는 날 경고(`docs/design-closed-days.md`)와 같은 원칙을 따른다: 확실히 읽을 수 있는 모양만 판단하고, 나머지는 원문을 보여 주며,
모든 경우에 "정확하지 않을 수 있으니 직접 연락해 확인" 안내와 문의처를 붙인다. 가능/불가능 판정에는 영향을 주지 않는다.

## 이 기능이 하는 일
이 서비스는 장소마다 도착·출발 시각을 이미 계산한다. 그 시각이 한국관광공사에 등록된 이용시간과 맞는지 본다.
- 영업 시작 전에 도착한다 (`before-open`)
- 영업 종료 뒤에 도착한다 (`after-close`)
- 입장마감·마지막 주문 시각 뒤에 도착한다 (`after-last`)
- 체류하는 동안 영업이 끝난다 (`stay-over`)

## 데이터 (실제로 조회한 이용시간 37건)
정해진 형식이 없는 자유 텍스트다. 판독 가능한 모양은 다음과 같다.
| 모양 | 예 |
|---|---|
| 한 구간 + 입장마감·마지막 주문 | `10:00~22:00 (마지막 주문 21:30)` |
| 상시 개방 | `상시 개방` |
| 달별 | `[1월~2월/11월~12월]09:00~17:00 (입장마감 16:00)[3월~5월/9월~10월]…` (11월~2월처럼 한 바퀴 도는 범위 포함) |
| 요일별 | `[월요일~목요일/일요일]10:00~21:00[금요일~토요일]…` |
| 평일·주말 | `평일 10:00~22:30 주말 10:00~23:00` |

판단하지 않는 모양(확인 필요): 구역별(`[일반관람]…[전시관]…`), 하절기·동절기, 브레이크타임·쉬는 시간,
점포·시설·매장별 상이, 밤 12시를 넘기는 시간(`~익일`, 닫는 시각이 여는 시각보다 앞).
결과: 37건 중 29건 판단, 8건 확인 필요.

## 상태 (`checkHours`)
| 상태 | 조건 | 화면 |
|---|---|---|
| `bad` | 위 네 가지 문제 중 하나 | 경고 카드 + 일정 옆 "영업시간 확인" 표시 + 확인 목록 문구 |
| `check` | 판독 불가, 해당하는 달·요일 구간 없음, 도착 시각을 모름 | 카드 없이 확인 목록에만 "자동으로 판단하지 못했습니다" |
| `ok` | 영업시간 안에 도착 | 확인 목록에 약한 문구 |
| `none` | 등록 없음 | 표시 없음 |

판단하지 못한 곳마다 카드를 만들면 화면이 길어져서(약 1/5이 확인 필요) 카드는 `bad`일 때만 만든다. 쉬는 날이면 영업시간은 따로 경고하지 않는다.

## 구조
- `js/core/openingHours.js`: `parseHours(text)`, `checkHours(parsed, 'YYYY-MM-DD', { arrive, depart })`. 순수 함수. 날짜 판독은 `closedDays.js`의 `parseYmd`를 쓴다.
- `js/app.js`: 일정 계산이 끝난 뒤 장소별 `{ arrive, depart }`로 판단한다. 출발지는 도착 시각이 없어 보지 않는다.
  도착지는 도착만, 경유지는 도착·출발을 본다. 한국관광공사 장소인 도착지도 판단한다.
- 서버는 바꾸지 않는다(이용시간 `hours`를 이미 내려준다).
- 테스트: 조회한 실제 문자열 28종(중복 제외)을 그대로 고정값으로 쓴다(`tests/openingHours.test.js`).

## 알려진 한계
- 등록된 이용시간 자체가 부정확할 수 있다. 공휴일·특별 휴관은 반영하지 않는다.
- 도착·출발 시각은 이동시간 계산 결과라 실제와 다를 수 있다(특히 대중교통은 모든 구간을 시작 시각 기준으로 계산).
- 자정을 넘기는 영업(예: 18:00~익일 02:00)과 구역별 시간은 판단하지 않는다.
